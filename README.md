# Hospital Management System

Generated by the AI Software Development Team.

## Files
- `frontend/index.html`: local redirect to login.
- `frontend/home.html`: generated homepage.
- `frontend/login.html` and `frontend/register.html`: forms connected to Flask authentication.
- `frontend/dashboard.html`: prompt-aware module dashboard.
- `frontend/js/config.js`: configure the backend URL here.
- `backend/app.py`: Flask API with password hashing and SQLite user storage.

## Run locally
1. Open a terminal in `backend`.
2. Create and activate a virtual environment, then run `pip install -r requirements.txt`.
3. Set a unique `SECRET_KEY` environment variable.
4. Run `python app.py`.
5. In `frontend/js/config.js`, keep `API_BASE_URL` set to `http://127.0.0.1:5001`.
6. In a second terminal, run `python -m http.server 8000` from `frontend`.
7. Open `http://127.0.0.1:8000`.

## Deploy
Deploy `frontend` to Vercel and `backend` as a separate Flask web service. Set `API_BASE_URL` to the backend HTTPS URL and `FRONTEND_ORIGIN` to the exact Vercel origin. For cross-site session cookies, use HTTPS and configure `SESSION_COOKIE_SAMESITE=None` and `SESSION_COOKIE_SECURE=true`. Set a strong secret in the hosting environment. SQLite on ephemeral hosting may not persist; use a managed database for production.

## Limitations and security
Passwords are hashed by the backend and are not stored in browser storage. Dashboard module records are still demo CRUD stored in this browser; add authenticated backend endpoints and database tables for real persistent module data. Security headers do not guarantee removal of Chrome Safe Browsing warnings. Review the generated source and dependencies before deployment and request a Safe Browsing review if a warning remains.
